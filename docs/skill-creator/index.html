Skills que se descubren y se ejecutan

La skill skill-creator produce el directorio de una skill nueva con una forma concreta: metadatos que un validador acepta o rechaza, un SKILL.md corto escrito en imperativo y carpetas de apoyo cuyo contenido se abre solo cuando la operación lo pide. El paquete es de terceros y está fijado a una versión: esta página describe lo que hace y remite a sus ficheros para las reglas.

Qué hace

Convierte un encargo de autoría en un directorio que un agente puede descubrir por sus metadatos, cargar por partes y ejecutar sin adivinar. El procedimiento completo vive en SKILL.md; aquí está el resultado que produce y lo que deja fuera.

SituaciónQué hace la skill
Hay que crear una skill nueva de agente.Elige un name y redacta una description en tercera persona, con disparadores positivos y negativos.
Los metadatos están escritos y hay que saber si sirven.Ejecuta el validador y no sigue al directorio hasta que termina con código 0.
Hay que redactar las instrucciones que el agente va a ejecutar.Las escribe en imperativo y tercera persona, numeradas y cronológicas, con cada decisión explícita y un término por concepto.
El cuerpo de la skill crece o el contexto se hincha.Mueve el esquema, la plantilla o el conjunto de reglas a references/ o a assets/, deja el cuerpo bajo 500 líneas y ordena leer ese fichero solo cuando toca.
Una comprobación es frágil o repetitiva: una expresión regular, un análisis complejo, código repetitivo.La empaqueta como CLI de un solo propósito en scripts/, con el éxito por stdout y el error por stderr.
El borrador está terminado.Busca huecos donde el agente tendría que suponer algo y recorre la checklist de references/checklist.md.

Una skill de terceros, fijada a una versión. Su origen y el commit fijado están registrados en la sección Skills en uso del README.md. El paquete vive en .skills/skill-creator/ y no es de autoría propia: se usa tal como está y, cuando toca actualizar, se sustituye entero; no se edita en este repositorio. Esta página describe lo que hay y no propone cambios de redacción ni extensiones del paquete.

Lo que no hace. Su disparador es crear directorios de skill nuevos: no mantiene los que ya existen, no escribe documentación general, no envuelve código de librería que no es para un agente y no produce README.md.

Cuándo se activa

Las dos columnas están en la description del frontmatter. Los disparadores negativos evitan que la skill se active en la conversación equivocada; no son cortesía.

Se activa paraNo se activa para

La descripción decide. Es el único texto que el agente ve antes de disparar la skill, y por eso el procedimiento empieza por ella: nombre y descripción primero, validador después.

3

Cómo se usa

El procedimiento cubre metadatos, directorio, SKILL.md, scripts, composición opcional, auditoría final y gestión de errores. Esta página documenta la única puerta automática del recorrido, el validador de metadatos, y el significado de lo que imprime. Los límites que aplica a name y description están en el paso 1 de SKILL.md y en el propio script. La ruta está escrita como la escribe el SKILL.md, relativa a la carpeta de la skill; desde la raíz del repositorio el fichero está en .skills/skill-creator/scripts/validate-metadata.py.

python3 scripts/validate-metadata.py --name "[name]" --description "[description]"

Qué significa cada salida

SalidaQué imprimeQué significa
0SUCCESS: Metadata is valid and optimized for discovery. por stdout.Los metadatos pasan las comprobaciones del script. El procedimiento continúa con el directorio.
1Uno o más mensajes por stderr, cada uno con su prefijo: NAME ERROR:, DESCRIPTION ERROR: o STYLE WARNING:.Al menos una comprobación falla. Se reescribe el campo que el mensaje nombra y se vuelve a ejecutar hasta obtener 0.

Tres detalles del validador, dichos como son. STYLE WARNING no es un aviso: termina con código 1 igual que los errores, y el apartado de errores de SKILL.md lo nombra STYLE ERROR mientras el script imprime STYLE WARNING. La comprobación de estilo es una heurística por palabras completas —i, me, my, we, our, you, your—, así que detecta lo que su lista cubre, no todo lo que un revisor vería. Y sin --description el script recibe una cadena vacía y devuelve éxito: la longitud se comprueba sobre el texto que le llega.

El error no se rodea

El SKILL.md pide autocorregir el metadato con lo que dice stderr y repetir hasta que el script termine bien. No hay una segunda vía documentada dentro del procedimiento: mientras el validador falle, no se crea la estructura.

Qué contiene el paquete

Ninguna documentación para personas: el paquete se carga en la ventana de contexto del agente, así que lo que no se ejecuta no tiene sitio dentro.

├── SKILL.md                       # los pasos y la gestión de errores

├── assets/

└── scripts/
    └── validate-metadata.py       # nombre y descripción, con códigos de salida

6

Preguntas cortas

Lo que no se resuelve leyendo las secciones anteriores.

¿Por qué el name tiene que coincidir con la carpeta?

Porque el nombre es el identificador con el que se enruta la skill y la carpeta es el sitio donde vive: name: angular-testing vive en angular-testing/SKILL.md. Si no coinciden, la ruta y los metadatos dicen cosas distintas.

¿Sirve una cuarta carpeta si mi skill la necesita?

La estructura estándar son tres: scripts/, references/ y assets/, y la checklist exige que sean esas. Si el contenido no encaja en ninguna, el problema está en la forma de la skill.

¿Un README.md dentro de la skill, aunque sea corto?

No: el paso que monta el directorio prohíbe los ficheros para personas, y la checklist nombra README.md y CHANGELOG.md entre los que no pueden estar. La documentación va fuera del paquete, en docs/, donde no consume contexto.

¿Hace falta una skill enrutadora?

Solo si la skill es compleja. La composición es un paso opcional: una skill de alto nivel que deriva a otras según la condición. Para un procedimiento corto, añadir esa capa es una lectura de más.

¿Los scripts pueden ser código de librería reutilizable?

No: son CLIs de un solo propósito que reciben argumentos. La lógica de librería de larga vida pertenece a las CLI estándar del repositorio, no al paquete de la skill.

Verificación

El frontmatter se valida y la puerta del repositorio se ejecuta; una skill con metadatos inválidos no se declara terminada.

python3 scripts/validate-metadata.py --name "" --description ""
python3 scripts/check-repo.py
CódigoSignificado
0Metadatos y puerta del repositorio sin hallazgos.
distinto de 0Algún comando falla; se corrige antes de cerrar.

La validación comprueba la forma de los metadatos; que la descripción describa de verdad cuándo usar la skill se contrasta con la guía de autoría.
