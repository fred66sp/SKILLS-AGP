Buenas prácticas para crear skills de agente

Cómo escribir skills de nivel profesional, validarlas con un LLM y mantener una ventana de contexto ajustada. La especificación de agentskills.io es la referencia estricta; esta guía la resume y añade el método de validación.

1

Estructura de una skill

estructura obligatoria

Toda skill sigue esta estructura de directorios. El paquete contiene lo que el agente necesita para ejecutar, no documentación para personas.

skill-name/
├── SKILL.md              # Obligatorio: metadatos + instrucciones centrales (<500 líneas)
├── scripts/              # Código ejecutable (Python/Bash) como CLIs minúsculas
├── references/           # Contexto complementario (esquemas, cheatsheets)
└── assets/               # Plantillas o archivos estáticos usados en la salida

SKILL.md

Actúa como el «cerebro». Úsalo para la navegación y los procedimientos de alto nivel.

references/

Contexto complementario. Enlázalos directamente desde SKILL.md y mantenlos a un único nivel de profundidad.

scripts/

Operaciones frágiles o repetitivas donde la variación es un error. No empaquetes aquí código de librería.

assets/

Plantillas, esquemas y archivos estáticos que la skill usa para producir su salida.

2

Optimiza el frontmatter para el descubrimiento

El name y la description del frontmatter son los únicos campos que el agente ve antes de disparar una skill. Si no están optimizados para el descubrimiento y no son lo bastante específicos, tu skill es invisible.

name: estricto y comprobable

  • Entre 1 y 64 caracteres.
  • Solo letras minúsculas, números y guiones simples; sin guiones consecutivos.
  • Debe coincidir exactamente con el nombre del directorio padre.

description: optimizada para el disparo

  • Máximo 1024 caracteres.
  • Describe la capacidad en tercera persona.
  • Incluye disparadores positivos y negativos: cuándo sí y cuándo no.

El nombre manda en la ruta. name: angular-testing debe residir en angular-testing/SKILL.md. La descripción es el único metadato que el agente ve para el enrutamiento.

Mal

«React skills.»

Demasiado vago: no dice qué hace, cuándo se activa ni cuándo no.

Bien

«Creates and builds React components using Tailwind CSS. Use when the user wants to update component styles or UI logic. Don't use it for Vue, Svelte, or vanilla CSS projects.»

Capacidad, disparadores y límites en la misma descripción.

3

Divulgación progresiva y gestión de recursos

Mantén una ventana de contexto impecable cargando información solo cuando sea necesario. SKILL.md es el «cerebro» de la lógica de alto nivel; delega los detalles en subdirectorios.

  • Mantén SKILL.md ligero. Limita el archivo principal a <500 líneas. Úsalo para la navegación y los procedimientos principales.
  • Usa subdirectorios planos. Mueve el contexto voluminoso a las carpetas estándar y mantén los archivos exactamente a un nivel de profundidad: references/schema.md, no references/db/v1/schema.md.
  • Carga justo a tiempo (JiT). Indica explícitamente al agente cuándo debe leer un archivo. No verá estos recursos hasta que se lo indiques, por ejemplo: «Consulta references/auth-flow.md para los códigos de error concretos».
  • Rutas explícitas. Usa siempre rutas relativas a la carpeta de la skill con barras inclinadas (/), independientemente del sistema operativo. Pi resuelve una ruta relativa contra el directorio del SKILL.md, no contra el directorio de trabajo.

Las skills son para agentes, no para personas. El fin es mantener la ventana de contexto ajustada y evitar un consumo innecesario de tokens.

No crees

Archivos de documentación

README.md, CHANGELOG.md o INSTALLATION_GUIDE.md dentro del paquete de la skill.

Lógica redundante

Si el agente ya resuelve una tarea de forma fiable sin ayuda, elimina la instrucción.

Código de librería

Referencia herramientas existentes o incluye scripts minúsculos de un solo propósito. El código de larga vida pertenece a los directorios CLI del repositorio.

4

Instrucciones procedimentales, no prosa

Crea instrucciones para LLM, no para personas. Un procedimiento explícito reduce la interpretación y los pasos inventados.

  • Usa numeración paso a paso. Define el flujo de trabajo como una secuencia cronológica estricta. Si hay un árbol de decisión, mapéalo con claridad: «Paso 2: si necesitas mapas de código fuente, ejecuta ng build --source-map. En caso contrario, salta al paso 3».
  • Aporta plantillas concretas. Los agentes hacen coincidencia de patrones excepcionalmente bien. En lugar de gastar párrafos describiendo una salida JSON, coloca una plantilla en assets/ e indica al agente que copie su estructura.
  • Escribe en imperativo y en tercera persona. Formula las instrucciones como órdenes directas: «Extrae el texto…», no «Voy a extraer…» ni «Deberías extraer…».

Coherencia y especificidad

Terminología idéntica

Elige un único término para un concepto concreto y úsalo en todo el paquete. Los sinónimos introducen ambigüedad.

La palabra propia del dominio

Usa la terminología más específica del dominio que describes. En Angular, «template» antes que «html», «markup» o «view».

5

Scripts deterministas para operaciones repetitivas

No pidas al LLM que escriba lógica de análisis compleja o código repetitivo desde cero cada vez que ejecuta una skill.

  • Delega las tareas frágiles o repetitivas. Si el agente necesita analizar un conjunto de datos complejo o consultar una base de datos concreta, dale un script probado de Python, Bash o Node para ejecutar desde scripts/.
  • Gestiona los casos límite con elegancia. Un agente se apoya en la salida estándar (stdout/stderr) para saber si un script ha funcionado. Escribe scripts que devuelvan errores muy descriptivos y legibles, para que el agente sepa cómo autocorregirse sin intervención del usuario.

La variación es el enemigo. Si un paso exige repetir exactamente la misma lógica, conviértelo en un script de un solo propósito y haz que el SKILL.md lo invoque.

6

Composición de skills

Puedes componer skills —también conocidas como skills enrutadoras— si quieres incluir una skill de forma condicional o crear una skill compuesta por subskills.

---
name: build-project
description: ...
---

## Descripción general
...

## Objetivos de compilación

### Cliente

Para compilar el cliente en un binario desplegable, consulta [ruta a las skills].

### Servidor

Para compilar el servidor en un binario desplegable, consulta [ruta a la skill].

...

El enrutador no copia el contrato. Decide a qué skill derivar y deja que la skill de destino conserve sus propias reglas. Así no hay dos fuentes de verdad.

7

Guía de validación

Como los LLM van a usar tus skills, la mejor forma de asegurar que son útiles es validarlas en colaboración con un LLM. Un benchmark popular es SkillsBench, que puede servir de inspiración; para evaluar si tus skills funcionan bien y evitar regresiones, revisa skillgrade.

Cuatro conversaciones, cuatro controles. Copia cada prompt en un chat nuevo y trabaja sobre la respuesta. El botón de copiar incluye todo el texto del panel.

Validación del descubrimiento

Los agentes cargan las skills basándose estrictamente en el frontmatter YAML. Prueba cómo interpreta un LLM tu descripción de forma aislada, para evitar falsos disparos: por ejemplo, que se active para una aplicación React cuando está pensada para Angular.

Prompt · descubrimiento

Estoy creando una Agent Skill basada en la especificación de agentskills.io. Los agentes decidirán si cargan esta skill basándose enteramente en los metadatos YAML de abajo.

name: angular-vite-migrator
description: Migrates Angular CLI projects from Webpack to Vite and esbuild. Use when the user wants to update builder configurations, replace webpack plugins with rollup equivalents, or speed up Angular compilation.

Basándote estrictamente en esta descripción:

  1. Genera 3 prompts de usuario realistas que con total seguridad deberían disparar esta skill.
  2. Genera 3 prompts de usuario que suenen parecido pero que NO deberían disparar esta skill (por ejemplo, migrar una aplicación React a Vite o simplemente actualizar versiones de Angular).
  3. Critica la descripción: ¿es demasiado amplia? Propón una reescritura optimizada.

Además, encarga a los agentes tareas que esperas que disparen la lectura de una skill e inspecciona su proceso de razonamiento. Itera con el agente para identificar por qué eligió —o no— determinadas skills.

Validación de la lógica

Asegúrate de que tus instrucciones paso a paso son deterministas y no fuerzan al agente a alucinar pasos que faltan. Entrega al LLM tu SKILL.md completo y el árbol de directorios.

Prompt · lógica

Aquí tienes el borrador completo de mi SKILL.md y el árbol de directorios de sus archivos de apoyo.

├── SKILL.md
├── scripts/esbuild-optimizer.mjs
└── assets/vite.config.template.ts

[Pega aquí el contenido de tu SKILL.md]

Actúa como un agente autónomo que acaba de disparar esta skill. Simula tu ejecución paso a paso ante la petición «Migra mi aplicación Angular v17 a Vite».

Para cada paso, escribe tu monólogo interno:

  1. ¿Qué estás haciendo exactamente?
  2. ¿Qué archivo o script concreto estás leyendo o ejecutando?
  3. Señala cualquier bloqueo de ejecución: indica la línea exacta en la que te ves obligado a adivinar o alucinar porque mis instrucciones son ambiguas (por ejemplo, cómo mapear los archivos de entorno de Angular a import.meta.env de Vite).

Pruebas de casos límite

Fuerza al LLM a buscar vulnerabilidades, configuraciones no soportadas y estados de fallo propios de las herramientas web. Pídele que ataque tu lógica.

Prompt · casos límite

Ahora cambia de rol. Actúa como un probador de QA implacable. Tu objetivo es romper esta skill.

Hazme entre 3 y 5 preguntas muy específicas y exigentes sobre casos límite, estados de fallo o respaldos ausentes en el SKILL.md. Céntrate en:

  • ¿Qué ocurre si scripts/esbuild-optimizer.mjs falla por una dependencia CommonJS heredada?
  • ¿Qué ocurre si el angular.json del usuario contiene builders de Webpack muy personalizados (@angular-builders/custom-webpack) que Vite no soporta?
  • ¿Hay suposiciones implícitas sobre el entorno Node del usuario que yo haya asumido?

No corrijas estos problemas todavía. Hazme solo las preguntas numeradas y espera a que las responda.

Refinamiento de la arquitectura

A menudo los LLM intentan meter archivos de configuración grandes directamente en el prompt principal. Usa este paso para imponer la divulgación progresiva y reducir el consumo de tokens. Pide al LLM que aplique tus correcciones y reestructure la skill.

Prompt · arquitectura

A partir de mis respuestas a tus preguntas sobre casos límite, reescribe el archivo SKILL.md aplicando estrictamente el patrón de diseño de divulgación progresiva:

  1. Mantén el SKILL.md principal estrictamente como un conjunto de pasos de alto nivel, con comandos en imperativo y tercera persona (por ejemplo, «Ejecuta el script de esbuild», «Lee la plantilla de configuración de Vite»).
  2. Si hay reglas densas, plantillas grandes de vite.config.ts o esquemas complejos de angular.json que ahora mismo están en el archivo, elimínalos. Indícame que cree un archivo nuevo en references/ o assets/, y sustituye el texto de SKILL.md por una orden estricta de leer ese archivo concreto solo cuando sea necesario.
  3. Añade al final una sección dedicada a la gestión de errores que incorpore mis respuestas sobre los respaldos de Webpack y la resolución de CommonJS.

La especificación manda. Esta guía la resume y añade pruebas de validación; si hay conflicto, manda agentskills.io. Para documentación exhaustiva, consulta la documentación de Claude.
